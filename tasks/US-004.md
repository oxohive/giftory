# US-004: Fix Email Verification and Password Reset Links (Gap G7)

- **Parent Feature:** [FEAT-005 Customer Accounts](../docs/features/customer-accounts.md)
- **Status:** Done (env var required in production)
- **Priority:** High
- **Evidence / Origin:** `apps/storefront/docs/backend-api-contract.md` — Gap G7, marked **Open**.

## User Story

As a new shopper,  
I want the verification link in my registration email to open the storefront's verification page,  
so that I can complete my registration without being redirected to an unfamiliar system portal.

## Context

When a shopper registers or requests a password reset, the Open Mercato backend sends a transactional email containing a link. Currently that link points to the Open Mercato built-in portal (the admin/portal interface), not the storefront's `/account/verify` or `/account/reset-password` routes. This means:
- Shoppers cannot self-serve email verification from the storefront.
- Password reset links open the wrong interface.
- In development, email is not sent at all; manual verification is required in the admin.

This is Gap G7 in the API contract document.

## Acceptance Criteria

1. Given a shopper registers at `/account/register`, when the verification email arrives, then clicking the link opens the storefront's `/account/verify?token=<token>` page.
2. Given a shopper requests a password reset, when the reset email arrives, then clicking the link opens the storefront's `/account/reset-password?token=<token>` page.
3. The storefront pages at those routes handle the token, call the backend to complete verification/reset, and show success or error feedback.

## Scope

- **Included:** Backend configuration to point email links at the storefront origin; storefront route handlers for verify and reset-confirm.
- **Excluded:** Email delivery itself (requires an email provider like Resend to be configured).

## Dependencies

- Open Mercato `customer_accounts` module — configurable redirect URL for email links (mechanism to be verified).
- `MERCATO_TENANT_ID`, `MERCATO_ORGANIZATION_ID`, `NEXT_PUBLIC_SITE_URL` env vars.

## Implementation Notes

Open Mercato builds email verification links as `{PLATFORM_PORTAL_BASE_URL}/{orgSlug}/portal/verify?token=...`. The path prefix `/{orgSlug}/portal/` is always appended by the framework (`core:customer_accounts/lib/customerUrl.js#urlForCustomerOrg`).

### What was implemented

1. **`apps/storefront/next.config.ts`** — Added `redirects()` that catch `/:orgSlug/portal/verify` and `/:orgSlug/portal/reset-password` and forward them (with query string) to `/account/verify` and `/account/reset-password` respectively. This means when `PLATFORM_PORTAL_BASE_URL` is set to the storefront origin, email links land on the correct storefront pages.

2. **`/account/verify`** — Already existed; accepts `?token=` and calls `POST /api/customer_accounts/email/verify`.

3. **`/account/reset-password`** — **Created** (`apps/storefront/src/app/account/reset-password/page.tsx`). Accepts `?token=` and renders a `ResetPasswordForm` component that calls `POST /api/customer_accounts/password/reset-confirm`.

4. **`apps/storefront/src/components/account/reset-password-form.tsx`** — Created; form with new-password + confirm-password fields, success/error states.

5. **`apps/storefront/src/lib/api/customer.ts`** — Added `confirmPasswordReset(token, newPassword)` method.

### Required production config (manual step)

Set in `apps/mercato/.env`:
```
PLATFORM_PORTAL_BASE_URL=https://<storefront-domain>
```

This tells Open Mercato to embed the storefront URL in outgoing emails. Without this, emails still link to `http://localhost:3000/{orgSlug}/portal/verify` in dev, and the feature is effectively disabled.

In development: email delivery requires an email provider (Resend) — verify manually through the admin console at `/backend` until email is configured.
